# HQ MCP 서버 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Claude Code가 HQ에 등록된 Windows 서버 여러 대에 조회 스크립트를 한 번에 돌리고, 확인을 받은 스크립트를 실행할 수 있게 하는 MCP 서버(`python -m hq.mcp`)를 만든다.

**Architecture:** Claude Code가 자식 프로세스로 띄우는 표준 입출력 JSON-RPC 서버다. 호출마다 `inventory.json`과 `mcp-access.json`을 읽고, 서버마다 `powershell.exe`를 하나씩 띄워 `New-PSSession`으로 접속한다. `run_query`는 이 PC의 PowerShell 파서로 만든 문법 트리를 허용 목록으로 검사한 뒤에만 실행하고, `run_script`는 Claude Code의 확인 창에 맡긴다. HQ 창(`hq.app`)과는 코드와 자료만 함께 쓰고 실행 중인 창을 거치지 않는다.

**Tech Stack:** Python 3.12, uv, pytest + pytest-timeout, Windows PowerShell 5.1. 새 의존성은 없다(MCP SDK를 쓰지 않고 JSON-RPC를 직접 쓴다. 스펙 17장이 구현자에게 맡긴 선택이다. 웹 서버 패키지가 따라오지 않고 exe에 들어갈 것도 없다).

**Spec:** `docs/specs/2026-11-04-hq-mcp-design.md` (승인됨). 기준 문서는 `docs/specs/2026-10-15-hq-design.md`. 이 계획은 스펙을 근거로 한다. 실행하는 사람은 두 문서를 함께 읽는다. 아래에서 "스펙 N장"은 MCP 스펙을 가리킨다.

## Global Constraints

- **실서버 금지.** 구현과 자동 테스트는 실서버에 어떤 트래픽도 보내지 않는다(접속, 포트 확인, ping, 이름 풀이 뒤 접속 모두). 건드리지 않기로 정한 운영 서버는 어떤 경우에도 쓰지 않는다. 실서버 확인은 ⛔ 체크포인트에서 사용자가 한다. Claude는 실서버 비밀번호를 다루지 않는다.
- 테스트는 실제 `%LOCALAPPDATA%\hq`를 읽지 않는다. 폴더, 실행기, probe, 이름 풀이를 주입하거나 테스트 프로세스의 `LOCALAPPDATA`를 임시 폴더로 바꾼다. `tests/integration/conftest.py`는 `LOCALAPPDATA`를 바꾸지 않는다.
- 개발 중에는 진짜 `hq.mcp`를 Claude Code에 등록하지 않는다. 등록은 체크포인트 A의 가짜 서버와 체크포인트 B의 설치뿐이고, 둘 다 사용자가 한다.
- 스펙 15장의 공격 표와 `Format` 줄은 어떤 경우에도 실제로 실행하지 않는다. 조회 검사 테스트는 검사만 부르고 실행기를 부르지 않는다. WMI `Format`, `Win32_Product`, `Win32_PingStatus`를 조회하는 코드를 쓰지 않는다.
- 표준 출력에는 MCP 메시지만 쓴다. 로그는 `logs\hq-mcp.log`와 표준 오류로 보낸다. `hq.app.configure_logging`과 `hq.log`를 쓰지 않는다.
- `hq.mcp`는 `hq.bridge`, `hq.app`, `hq.sessions`를 가져오지 않는다. `hq.app`은 `hq.mcp`를 가져오지 않는다. `hq.spec`과 `scripts/build.ps1`은 바꾸지 않는다.
- `inventory.json`은 읽기만 한다. MCP에서 저장하지 않는다. 수신 포트를 열지 않는다.
- Python은 비밀번호를 풀지 않는다. 비밀번호 파일 경로와 `username`, 서버 id는 Claude에게 가는 글(결과, 오류)에 넣지 않는다.
- PowerShell에 넘기는 값은 ASCII JSON으로 표준 입력에 넣는다. `FromBase64String`을 쓰지 않는다(AhnLab V3가 막는다).
- 스크립트는 글자로 서버에 보내 서버에서 스크립트 블록으로 만든다. 이 PC에서 `[scriptblock]::Create`로 만들어 `Invoke-Command`에 넘기지 않는다(스펙 8.2).
- 접속 실패를 다시 시도하지 않는다. 틀린 비밀번호로 거듭 접속하면 계정이 잠긴다.
- 스펙의 숫자: 스크립트 1~20,000자, `timeout_seconds` 5~1500(기본 120), 호출 전체 1500초, 동시 실행 8, 서버별 메모리 40,000자, 결과 JSON 크기 30,000(ASCII 1, 그 밖의 글자 4), 조회 검사 10초, 이름 풀이 2초, 기능 설명 4,096자, 강제 종료 전 정리 시간 10초.
- `src/hq/ps/`의 템플릿은 BOM 없는 UTF-8이다. `tools/**/*.ps1`은 BOM 있는 UTF-8이다(`tests/test_ps_files.py`가 검사한다).
- 사용자와 Claude에게 보이는 글(오류, 기능 설명, 명령줄 출력)은 한국어로 쓴다.
- 공개 저장소다. 실제 서버 주소, 컴퓨터 이름, 소속, 계정 정보를 코드, 테스트, 문서에 넣지 않는다. 시험 주소는 `10.0.1.21`(스펙의 예)과 문서용 주소(`192.0.2.0/24`, `198.51.100.0/24`)만 쓴다.
- TDD: 테스트를 먼저 쓰고 기대한 이유로 실패하는 것을 확인한 뒤 구현한다. 커밋은 모든 테스트가 통과할 때만 한다.
- 작업은 `main`이 아닌 가지 `mcp`에서 한다. 커밋 메시지는 영어 제목과 필요하면 본문만 쓴다. Claude/AI 표시(`Co-Authored-By` 등)를 넣지 않는다. git identity는 전역 설정을 쓴다. push는 사용자가 요청할 때만 한다.
- 테스트 명령: 전체 `uv run pytest`, 빠른 것만 `uv run pytest -m "not integration"`, 린트 `uv run ruff check . ; uv run ruff format --check .`. 통합 테스트 파일은 `pytestmark = pytest.mark.integration`으로 시작한다.

## Review Focus

스펙이 직접 말하지 않지만 쓰는 사람이 실제로 부딪히기 쉬운 입력이다. 각 줄의 테스트는 해당 태스크에 들어 있다.

1. **Claude가 `target`을 그대로 쓰지 않는다.** host만(`10.0.1.21`) 또는 별명만 보내는 일이 흔하다. 거절하되, 쓸 수 있는 `target` 목록과 "list_servers가 준 글자를 그대로 쓰라"는 안내를 돌려줘야 Claude가 스스로 고친다 → Task 13 `test_a_wrong_target_is_refused_and_the_valid_ones_are_listed`.
2. **`mcp-access.json`을 메모장으로 고친다.** 금지 해제는 파일을 직접 고치는 것이 유일한 방법이고, 메모장은 BOM을 붙인다. BOM이 있어도 읽혀야 하고, 깨졌으면 무엇이 틀렸는지 말해야 한다 → Task 4 `test_a_file_saved_by_notepad_with_a_bom_loads`, `test_a_broken_file_turns_everything_off_and_says_why`.
3. **모양이 어긋난 인자.** 주석뿐인 스크립트, `timeout_seconds`에 `"120"`이나 `30.5`나 `true`. 서버에 접속하기 전에 한 줄 오류로 거절해야 한다 → Task 13 `test_a_blank_script_and_a_non_integer_timeout_are_refused`.
4. **비밀번호가 바뀐 서버.** 한 대가 `AUTH_FAILED`여도 나머지는 결과가 나와야 하고, 실패한 서버에 다시 접속하지 않아야 한다 → Task 13 `test_a_failed_login_is_reported_once_and_never_retried`.
5. **없는 파일과 깨진 줄.** HQ를 한 번도 띄우지 않아 `inventory.json`이 없거나, 표준 입력에 JSON이 아닌 줄이 온다. 서버가 죽지 않고 이유를 알려야 한다 → Task 13 `test_a_missing_inventory_gives_an_empty_list_with_a_reason`, Task 1 `test_a_broken_line_gets_a_parse_error_and_the_next_request_still_works`.

### Task 1: 프로토콜과 기능 모양

**Files:**
- Create: `src/hq/mcp/__init__.py`, `src/hq/mcp/protocol.py`, `src/hq/mcp/schema.py`
- Test: `tests/test_mcp_protocol.py`, `tests/test_mcp_schema.py`

**Interfaces:**
- Produces (`protocol.py`):

```python
PROTOCOL_VERSIONS = ("2025-11-25", "2025-06-18", "2025-03-26", "2024-11-05")  # 앞이 최신

@dataclass(frozen=True)
class Tool:
    name: str
    description: str
    input_schema: dict
    annotations: dict
    meta: dict | None = None

@dataclass(frozen=True)
class ToolResult:
    text: str
    is_error: bool = False

Handler = Callable[[dict, threading.Event], ToolResult]  # (arguments, 취소 신호)

class Server:
    def __init__(self, tools: Sequence[Tool], handlers: Mapping[str, Handler], *, version: str,
                 reader: BinaryIO, writer: BinaryIO, name: str = "hq") -> None: ...
    def serve(self) -> None: ...  # 입력이 끝날 때까지. 끝나면 모든 취소 신호를 켜고 돌던 호출을 기다린다
```

- Produces (`schema.py`): `LIST_SERVERS = "list_servers"`, `RUN_QUERY = "run_query"`, `RUN_SCRIPT = "run_script"`, `REQUIRES_USER_INTERACTION = "anthropic/requiresUserInteraction"`, `tool_shapes() -> dict[str, dict]` (이름 → `{"input_schema", "annotations", "meta"}`).

**프로토콜 규칙** (테스트가 정하지 못하는 부분):
- 메시지는 한 줄에 하나, UTF-8, `ensure_ascii=False`. 쓰는 곳은 잠금 하나로 모은다.
- `initialize`: 요청의 `protocolVersion`이 `PROTOCOL_VERSIONS`에 있으면 그대로, 없으면 맨 앞 값을 돌려준다. `capabilities`는 `{"tools": {}}`.
- `tools/call`은 호출마다 스레드를 따로 쓴다. 처리기가 예외를 던지면 `isError`와 고정 문구(`내부 오류가 났습니다. logs\hq-mcp.log를 보세요.`)만 돌려주고 예외는 로그에 남긴다.
- `notifications/cancelled`의 `requestId`에 해당하는 취소 신호를 켠다. 이렇게 취소된 호출은 처리기가 끝나도 응답을 쓰지 않는다.
- 입력이 끝나면 돌던 호출의 취소 신호를 모두 켜고 끝나기를 기다린다. 이때는 응답을 막지 않는다(쓰다가 파이프가 닫혀 있으면 무시한다).
- 모르는 메서드는 `-32601`, 모르는 기능은 `-32602`, JSON이 아닌 줄은 `id: null`의 `-32700`. 모르는 알림은 무시한다.

`tests/test_mcp_schema.py`:

```python
def test_only_run_script_asks_the_user_and_the_value_is_json_true():
    shapes = tool_shapes()
```

```python
@dataclass(frozen=True)
class Access:
    enabled: tuple[tuple[str, str], ...] = ()   # (서버 id, 소문자 host)
    never: tuple[str, ...] = ()                 # canonical_ip로 고친 글자
    problem: str | None = None                  # 파일이 깨졌을 때의 이유. 이때 enabled와 never는 비어 있다

def load_access(path: Path) -> Access: ...      # 예외를 던지지 않는다. 파일이 없으면 Access()
def save_access(path: Path, access: Access) -> None: ...   # tmp에 쓰고 replace_with_retry. problem이 있으면 AccessError
def canonical_ip(text: str) -> str: ...         # IP가 아니면 ValueError. IPv4를 감싼 IPv6는 IPv4로

def usable(servers: Sequence[Server], access: Access) -> list[Server]: ...
```

**규칙:**
- 파일 모양은 스펙 6장의 JSON이다. `read_text_with_retry(path, encoding="utf-8-sig")`로 읽는다. `version`이 1이 아니거나, 모양이 틀리거나, `never`에 IP가 아닌 값이 있으면 `problem`에 무엇이 틀렸는지 적고 모든 서버를 꺼진 것으로 본다. 파일은 건드리지 않는다.
- `usable`: `inventory`에 있고, `enabled`에 같은 id와 같은 host(대소문자 무시)의 쌍이 있고, `display_name`에 제어 문자(`[\x00-\x1f\x7f-\x9f]`)가 없고, host가 IP일 때 그 주소가 `never`에 없는 서버.
- `resolve_host`: host가 IP면 `[canonical_ip(host)]`. 이름이면 데몬 스레드에서 `getaddrinfo(host, None)`을 불러 `timeout` 안에 나온 모든 주소를 `canonical_ip`로 고쳐 중복 없이 돌려준다. 실패하거나 시간이 넘으면 `None`.

**`run_on_server`:** 프로세스의 시간 한도는 `job.timeout_seconds + GRACE_SECONDS`. 상태는 `STATUS_BY_CODE`, 없는 코드는 `UNKNOWN`. 강제로 끝났으면 `TIMEOUT`과 `note="강제로 끝냈습니다. 서버에서 계속 돌 수 있습니다."`. 21이면 `note="시간 한도에서 멈췄습니다. 그 전까지는 서버에서 실행됐습니다."`. 12인데 `trusted`가 `None`이 아니고 `is_trusted(job.host, trusted)`면 `AUTH_FAILED`(기준 `Bridge._on_exit`의 규칙). `OSError`는 `SPAWN_FAILED`. `truncated`는 `total_chars`가 남긴 글자보다 많을 때.

**`mcp-run.ps1`:** 입력은 `{"host", "username", "secret_path", "script", "timeout_seconds", "cancel_path"}`.
1. `$hqTemplate` 옆의 `bootstrap.ps1`에서 `#region exitcode` 구역을 읽어 `Get-HqExitCode`를 정의한다. 분류 규칙을 두 벌로 만들지 않는다.
2. 비밀번호 파일을 읽어 자격 증명을 만든다. 실패하면 `저장된 비밀번호를 읽을 수 없습니다.`만 찍고(경로와 예외 글자를 넣지 않는다) 14.
3. `#region session` ~ `#endregion session`: `$session = New-PSSession -ComputerName $p.host -Credential $cred -Authentication Negotiate`. 실패하면 메시지를 찍고 `Get-HqExitCode`의 값으로 끝난다. 테스트는 이 구역만 바꾼다.
4. `$session`이 `$null`이거나 `State`가 `Opened`가 아니면 스크립트에 닿지 않고 1.
5. `Invoke-Command -Session $session -AsJob -ArgumentList $p.script -ScriptBlock { param($t) & ([scriptblock]::Create($t)) | Out-String -Stream -Width 200 }`. `-Session`이 없는 `Invoke-Command`는 템플릿 어디에도 없다.
6. 0.2초마다: 자식 작업의 `Output`, `Information`, `Warning`(앞에 `WARNING: `)을 표준 출력으로, `Error`를 표준 오류로 비운다(`ReadAll()`). `cancel_path` 파일이 생겼으면 22, 시간이 넘었으면 21: 둘 다 `Stop-Job` 뒤 세션을 지우고 끝난다.
7. 작업이 `Completed`면 0. `Failed`면 이유를 표준 오류에 찍고, 세션이 `Opened`가 아니면 20, 아니면 2. 어느 길로 끝나든 세션을 지운다.

**`build_result`:** `{"results": [{"target", "status", "output", "errors", "truncated", "output_chars", "seconds", "note"?}]}`를 `json.dumps(ensure_ascii=False, separators=(",", ":"))`로 만든다. `note`는 비어 있지 않을 때만 넣는다. 순서는 받은 순서다. 몫 나누기:
1. `output`과 `errors`를 비운 틀의 `weighted_size`를 `budget`에서 뺀 것이 나눌 양이다.
2. 서버마다 필요한 양은 JSON에 들어간 뒤의 크기다(`weighted_size(json.dumps(글자, ensure_ascii=False)[1:-1])`). 적게 필요한 서버부터 `min(필요한 양, 남은 양 // 남은 서버 수)`를 준다.
3. 한 서버 안에서는 `errors`가 `min(필요한 양, 몫 // 4)`를 먼저 갖고 `output`이 나머지를 갖는다. `output`이 남기면 `errors`가 더 쓴다.
4. 몫을 넘는 글자는 앞에서부터 잘라 남기고 `truncated`를 켠다. 이미 `truncated`인 것은 그대로 둔다.

- `run_script`: 이어서 "호출마다 사용자가 확인합니다. `reason`에는 무엇을 왜 하는지 한 줄로 쓰세요."

**`run_query`와 `run_script`의 순서** (스펙 8.1, 4.5). 1~6에서 걸리면 `ToolResult(is_error=True)`에 한 줄 이유를 담아 끝내고 어느 서버에도 접속하지 않는다:
1. 인자: `targets`는 글자 1개 이상, 중복 없음. `script`는 1~`SCRIPT_MAX`자이고 주석과 빈칸을 빼면 남는 것이 있다. `timeout_seconds`는 `bool`이 아닌 `int`로 5~1500. `reason`은 줄바꿈 없는 1~200자.
2. `load_access`와 `load_servers`를 **호출마다** 새로 읽는다. 문제가 있으면 그 이유.
3. `targets`가 모두 `usable` 서버의 `target_of`와 글자 그대로 같아야 한다. 아니면 "대상이 맞지 않습니다: … list_servers가 준 target을 그대로 쓰세요. 쓸 수 있는 target: …"(켠 서버만 적는다).
4. `never_ip_in(script, access.never)`: 있으면 거절하고 `audit.rejected`.
5. `run_query`만: `deps.check(script)`. 통과하지 못하면 이유들과 "삭제나 수정이 필요하면 사용자에게 이유를 말한 뒤 run_script를 쓰세요"를 돌려주고 `audit.rejected`.
6. host가 이름인 서버를 `deps.resolve`로 푼다. 나온 주소가 하나라도 `never`에 있으면 호출 전체를 거절한다. `None`이면 그 서버만 `UNRESOLVED`.
7. `audit.start`. 쓰지 못하면 "실행 기록을 쓰지 못해 실행하지 않았습니다."
8. 사전 확인: 비밀번호 파일이 없으면 `SECRET_UNREADABLE`. `deps.read_trusted()`를 한 번 읽어, 목록이 있는데 `is_trusted`가 아니면 `NOT_TRUSTED`. 남은 서버를 `deps.probe`로 한 번에 보고 닫혀 있으면 `UNREACHABLE`. 대상 밖의 서버는 보지 않는다.
9. 남은 서버를 스레드로 돌린다. 서버마다 `deps.slots`를 얻은 뒤: 취소 신호가 켜졌거나 남은 시간(`시작 + CALL_LIMIT_SECONDS − 지금`)이 15초 이하면 `NOT_STARTED`. 비밀번호 파일이 없으면 `SECRET_UNREADABLE`. 아니면 `timeout_seconds = min(요청 값, int(남은 시간) − GRACE_SECONDS)`, `cancel_path = data / "mcp-run" / call_id / f"{n}.cancel"`로 `deps.execute`를 **한 번** 부른다. 취소 신호가 켜지면 돌고 있는 서버의 `cancel_path` 파일을 만든다.
10. `audit.end`, `mcp-run\call_id` 폴더 삭제, `ToolResult(build_result(outcomes))`. 서버 실패는 `is_error`가 아니다.

`list_servers`: `{"servers": [{"target", "name", "nickname", "host", "group", "memo", "has_password"}]}`. 메모는 `clean_text`를 거친다. 설정이나 목록에 문제가 있으면 `{"servers": [], "note": 이유}`이고 `is_error`가 아니다.

## 스펙과 다르게 정한 것

- **MCP SDK를 쓰지 않는다.** 스펙 14장의 "`pyproject.toml`, `uv.lock`: MCP 의존성 추가"는 생기지 않는다. 스펙 17장이 맡긴 선택이고, 의존성이 없으므로 `hq.mcp`와 `mcp` 패키지 이름이 헷갈릴 일도 없다.
- **`remote_params`는 모든 명령에 적용하고 별칭만 명령별로 둔다.** 스펙 7.2는 "명령별로 실제 매개변수 정보에서 뽑는다"고 적었지만, 스펙의 공격 표에 `Get-ChildItem -PSSession $s`(그 명령에 없는 매개변수)가 있어 이름 다섯 개와 흔한 별칭 `CN`은 어디서나 막아야 표를 만족한다.
- **주석과 빈칸뿐인 스크립트를 거절한다.** 스펙 4.5는 길이만 정했다. 아무것도 하지 않을 스크립트로 서버에 접속하지 않게 했다.
- **결과에 `note`를 더했다.** 스펙 8.3이 "서버에서 계속 돌 수 있음을 함께 알린다"고 했는데 9장의 예시에는 실을 자리가 없다.
- **`CANCELLED`는 실행 기록에만 남는다.** 취소된 호출은 응답을 보내지 않으므로 스펙 9장의 상태 목록에 넣지 않았다.
