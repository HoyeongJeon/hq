# HQ 설계: 로컬 PowerShell 원격 콘솔

- 작성일: 2026-10-15
- 상태: 사용자 검토 대기
- 개발 방식: TDD (테스트 먼저, 13장)

## 1. 배경과 목표

### 1.1 문제

협회의 Windows 서버(50대 이하)에는 모두 mstsc(RDP)로 접속한다. 서버마다 공용 관리자 계정(Administrator, opsadmin)을 함께 쓰기 때문에, 한 사람이 RDP로 들어가면 먼저 들어와 있던 사람의 세션을 가져가 버린다.

### 1.2 목표

IT 관리자는 대부분 PowerShell만 있으면 된다. RDP 대신 PowerShell 원격(WinRM)으로 서버에 들어가는 도구를 만든다.

- 내 PC의 한 화면에서 서버를 골라 들어가 명령을 치고 결과를 본다.
- RDP 사용자와 부딪히지 않는다. WinRM 접속은 접속할 때마다 서버에 별도 프로세스가 생기므로 RDP 세션을 건드리지 않는다.

### 1.3 사용자

- 사용자 본인과 IT 관리자 동료, 2명.
- 두 사람 모두 모든 서버의 계정 정보를 안다.
- 서버 망에는 두 사람 PC의 IP만 열려 있다.
- 각자 자기 PC에서 따로 쓴다. 두 PC 사이에 공유하는 정보는 없다.

| 서버 설정 변경 | 가능(WinRM, 방화벽, 레지스트리). 2008·2003 서버에는 WMF 2.0 설치도 허용 |

## 3. 핵심 결정

| # | 결정 | 이유 |
|---|---|---|
| D1 | 전송은 WinRM HTTP 5985 | 2008 R2에서는 OpenSSH를 쓸 수 없다. 2012 이후는 WinRM이 기본으로 켜져 있다 |
| D2 | 인증은 NTLM(Negotiate) + 서버별로 저장한 자격 증명 | 관리자 PC가 도메인 밖에 있고 접속 계정이 서버 로컬 계정이라 Kerberos를 쓸 수 없다 |
| D3 | 내 PC에서 도는 로컬 웹 앱 + 실제 터미널 중계 | 목록·탭 화면은 웹으로 만들기 쉽고, 셸은 진짜 powershell.exe를 쓴다 |
| D4 | 셸을 다시 만들지 않는다 | `powershell.exe`와 `Enter-PSSession`을 ConPTY 안에서 그대로 돌리고 화면만 중계한다 |
| D5 | 모든 정보는 각자 PC에만 저장하고, 비밀번호는 DPAPI로 암호화 | 공유가 필요 없다. 서버나 클라우드에 기대지 않는다 |
| D6 | 배포는 `hq.exe` 파일 하나(PyInstaller) | 설치 없이 동료 PC에 복사해서 실행한다 |
| D7 | TDD | 사용자 요청 |

기술 구성: Python 3.12 + uv, FastAPI + uvicorn, pywinpty(ConPTY), openpyxl. 화면은 빌드 과정 없는 HTML/JS와 xterm.js(exe 안에 포함).

## 4. 구조

```
브라우저 (http://127.0.0.1:<port>)
   │  HTTP API + WebSocket, 127.0.0.1만
   ▼
hq.exe ─── %LOCALAPPDATA%\hq\  (inventory.json, secrets\*.dpapi)
   │  탭마다 ConPTY 안에서 실행
   ▼
powershell.exe (탭 1) ─┐
powershell.exe (탭 2) ─┼── WinRM 5985 (NTLM, 메시지 암호화) ──▶ 서버의 wsmprovhost.exe
powershell.exe (탭 N) ─┘                                         (명령은 여기서 실행)
```

- 명령은 서버에서 실행된다. 내 PC의 powershell.exe는 입력을 보내고 결과를 받아 그린다.
- 세션(자식 프로세스)은 hq.exe가 가진다. 브라우저는 화면일 뿐이라 새로고침하거나 닫아도 세션은 남는다.

### 4.1 구성 요소

모듈마다 책임은 하나다. 파일, 프로세스, 네트워크 같은 바깥 의존성은 주입받아서 테스트에서 가짜로 바꿔 끼울 수 있게 한다.

| 모듈 | 책임 | 의존 |
|---|---|---|
| `validation` | host·username 형식 검사 | 없음 |
| `inventory` | 서버 목록 모델, 읽기·검증·원자적 저장 | 파일 경로 |
| `secrets` | DPAPI 암호화, 비밀번호 파일 쓰기·삭제·존재 확인 | DPAPI(ctypes), 폴더 |
| `excel` | 양식 생성, xlsx 읽기, 행 검증·미리보기·적용 | openpyxl, inventory, secrets |
| `bootstrap` | 탭에서 실행할 PowerShell 명령 생성, 종료 코드 정의 | validation |
| `sessions` | 세션 상태(실행 중/끝남), 출력 링 버퍼, 구독자, 프로세스 수명 | 프로세스 생성기(주입) |
| `jobobject` | 자식 프로세스를 Job Object에 묶음 | Win32(ctypes) |
| `probe` | 5985 TCP 응답을 병렬로 확인 | asyncio |
| `trustedhosts` | TrustedHosts 읽기, 포함 여부 판단, 관리자 권한으로 추가 | powershell.exe, ShellExecuteEx |
| `server_setup` | 서버 설정 스크립트 생성 | 템플릿 |
| `web` | FastAPI 앱: 인증, API, WebSocket | 위 모듈들 |
| `main` | 단일 실행, 포트, 브라우저 열기, 종료 처리 | web |
| `static/` | 화면. 순수 로직(`*.mjs`)과 DOM 코드를 나눈다 | xterm.js |

## 5. 데이터

### 5.1 저장 위치

```
%LOCALAPPDATA%\hq\
├─ inventory.json        서버 목록과 설정 (비밀번호 없음)
├─ inventory.json.bak    직전 버전 (저장할 때마다 갱신)
├─ secrets\<id>.dpapi    서버별 비밀번호 (DPAPI)
├─ run.json              실행 중인 hq의 포트와 내부 비밀값
└─ logs\hq.log           사건 기록 (비밀번호와 화면 내용은 쓰지 않음)
```

사용자 폴더 이름에 한글이 들어 있으므로(`C:\Users\전호영`) 모든 경로 처리는 한글 경로에서 테스트한다.

### 5.2 inventory.json

```json
{
  "version": 1,
  "settings": { "admin_ips": ["10.0.0.50", "10.0.0.51"] },
  "servers": [
    {
      "id": "3f2a9c1e5b7d4e8f9a0b1c2d3e4f5a6b",
      "name": "WEB-PRD-01",
      "nickname": "웹01",
      "host": "10.0.1.21",
      "group": "운영",
      "username": "Administrator",
      "memo": "IIS 8.5\n매주 화 02시 백업"
    }
  ]
}
```

| 필드 | 필수 | 규칙 |
|---|---|---|
| id | 자동 | uuid4 hex. 바뀌지 않는다. 비밀번호 파일 이름으로 쓴다 |
| name | ○ | 1~100자 |
| nickname | | 0~50자. 비어 있으면 화면에 name을 보인다 |
| host | ○ | IPv4 주소 또는 호스트 이름(`A-Z a-z 0-9 . -`, 253자 이하). 대소문자를 무시하고 유일해야 한다. 서버를 구별하는 키다 |
| group | | 0~50자. 비어 있으면 "미분류" |
| username | ○ | `[A-Za-z0-9._-]` 1~64자. 앞에 `<접두>\` 하나를 허용한다(`.\Administrator`, `WEB01\Administrator`) |
| memo | | 여러 줄, 4000자 이하 |

- `settings.admin_ips`: 관리자 PC IP 목록(선택). 서버 설정 스크립트에서 5985 허용 IP로 쓴다(8.5).
- 저장은 원자적으로 한다. 같은 폴더에 임시 파일로 쓴 뒤 `os.replace`로 바꾼다. 바꾸기 전 파일은 `.bak`으로 남긴다.
- 파일이 깨져 읽을 수 없으면 덮어쓰지 않는다. 화면에 오류와 `.bak` 위치를 알린다.
- 백업이나 다른 PC로 옮길 때는 이 파일을 복사한다. 비밀번호 파일은 다른 PC나 계정에서 풀리지 않으므로, 옮긴 뒤 엑셀로 다시 등록한다.

### 5.3 비밀번호 파일

- 형식: 비밀번호를 UTF-16LE로 바꿔 DPAPI(CurrentUser, 추가 엔트로피 없음)로 암호화한 결과의 16진 문자열이다. 키 없이 실행한 `ConvertFrom-SecureString`의 출력과 같은 형식이라 `ConvertTo-SecureString`으로 바로 읽힌다.
- Python은 쓰기만 한다. 푸는 일은 탭의 powershell.exe가 직접 한다. 그래서 비밀번호는 명령줄, 환경 변수, 화면, 로그, API 응답 어디에도 나오지 않는다.
- 저장된 비밀번호는 다시 볼 수 없다. 덮어쓰기와 삭제만 된다. API는 저장되어 있는지 여부(`has_password`)만 돌려준다.

### 5.4 엑셀 일괄 등록

- 양식(xlsx, hq가 만들어 내려준다)
  - 첫 시트 `서버`: 1행은 머리글 `이름* | 닉네임 | IP/호스트* | 그룹 | ID* | PW* | 메모`, 2행부터 자료.
  - 모든 열을 텍스트 서식으로 만든다. 숫자로만 된 비밀번호나 IP가 숫자로 바뀌지 않게 하기 위해서다.
  - 둘째 시트 `설명`: 작성 요령과 예시. 예시를 첫 시트에 두지 않아 실수로 등록되지 않게 한다.
- 흐름: 파일 선택 → 미리보기(아직 저장하지 않음) → [등록] → 결과와 함께 "엑셀 파일에 비밀번호가 평문으로 들어 있으니 지우세요" 경고.
- 미리보기에서 행마다 상태를 보인다.
  - 신규: 등록한다.
  - 이미 등록된 host: 기본은 건너뛴다. [덮어쓰기]를 고르면 그 행의 값으로 모든 정보와 비밀번호를 바꾼다(빈 칸은 빈 값이 된다, id는 유지).
  - 오류: 필수 값 없음, 형식 오류, 파일 안에서 host 중복. 이유를 보이고 등록에서 뺀다.
  - 빈 행은 무시한다.
- 숫자로 저장된 셀은 텍스트로 바꾼다. 정수면 `.0`을 붙이지 않는다.
- 파일은 메모리에서만 읽고 디스크에 저장하지 않는다. 파일 크기는 5MB 이하.
- 미리보기 결과(비밀번호 포함)는 메모리에 10분 동안 둔다. 등록하거나 시간이 지나면 지운다.
- 비밀번호를 한꺼번에 바꿀 때도 같은 흐름을 쓴다. 바뀐 비밀번호로 엑셀을 만들어 [덮어쓰기]로 올린다.

## 6. 화면

- **왼쪽 목록**
  - 검색창, [+ 서버 추가], [엑셀 등록], [상태 새로고침].
  - 그룹별 서버 목록. 그룹은 이름순, "미분류"는 맨 끝. 서버는 화면 이름(별명, 없으면 name)순.
  - 항목마다 상태 점과 별명. ●는 5985 응답, ○는 응답 없음, 회색은 확인 전.
  - 검색은 이름, 별명, host, 메모를 대소문자 없이 찾고, 입력하는 대로 걸러진다.
- **서버 클릭 → 정보 패널**: 이름, 별명, host, 그룹, 계정, 비밀번호(저장됨/없음), 상태, 메모 전체. 버튼은 [접속] [정보 수정] [비밀번호 변경] [삭제] [서버 설정 스크립트].
- **서버 우클릭 → 메뉴**: 접속, 정보 수정, 비밀번호 변경, 삭제.
- **서버 더블클릭 → 새 탭에서 접속.** 같은 서버를 여러 번 열 수 있다.
- **삭제**: 확인 창에 열려 있는 탭 수를 보인다. 삭제하면 그 서버의 탭도 닫는다. 비밀번호 파일도 지운다.
- **탭**
  - 제목은 별명. 같은 서버의 둘째 탭부터 `별명 (2)`, `별명 (3)`.
  - 상태 색: 실행 중, 끝남.
  - 보고 있지 않은 탭에 새 출력이 생기면 제목 옆에 점.
  - 제목 아래에 메모 첫 줄. 누르면 메모 전체가 펼쳐진다.
  - [×]로 닫는다.
- **터미널(xterm.js)**
  - 원격 프롬프트는 `[10.0.1.21]: [웹01] PS C:\>`. 앞부분은 `Enter-PSSession`이 붙이고 `[웹01]`은 hq가 원격 프롬프트에 넣는다.
  - Ctrl+C: 선택한 글자가 있으면 복사, 없으면 실행 중인 명령 중단. Ctrl+V와 Ctrl+Shift+V는 붙여넣기.
  - 여러 줄을 붙여넣으면 먼저 "웹01(10.0.1.21)에 N줄을 실행합니다"라고 확인을 받는다.
  - Alt+1~9: n번째 탭으로 이동. Ctrl+Tab은 브라우저가 쓰므로 쓰지 않는다.
  - 스크롤백 10,000줄. 글꼴은 한글이 되는 고정폭 글꼴.
- **끝난 탭**: 입력을 잠그고, 덮개에 이유와 버튼(7.2 표)을 보인다. 이전 출력은 그대로 보인다.
- **배너**: "초기 설정 필요: TrustedHosts에 N대가 없습니다 [설정하기]".
- 서버 이름, 별명, 메모 같은 사용자 자료는 항상 글자(`textContent`)로만 넣는다. HTML로 해석하지 않는다.

## 7. 접속과 세션

### 7.1 접속 순서

1. 서버를 더블클릭하면 브라우저가 `POST /api/sessions {server_id}`를 보낸다.
2. hq가 먼저 확인한다. 실패하면 프로세스를 띄우지 않고 바로 안내한다.
   - 비밀번호 파일 없음 → 비밀번호 입력 창 → 저장한 뒤 계속.
   - host가 TrustedHosts에 없음 → "초기 설정 필요". TrustedHosts를 읽을 수 없으면 이 확인은 건너뛰고 7.4 분류에 맡긴다.
   - 5985 TCP 응답 없음(1초) → "서버 응답 없음".
3. hq가 ConPTY 안에서 `powershell.exe -NoLogo -NoProfile -NoExit -EncodedCommand <부트스트랩>`을 띄우고, 그 프로세스를 Job Object에 넣는다.
4. 부트스트랩이 내 PC의 PowerShell에서 실행된다.
   1. 맨 먼저 로컬 안전장치를 건다. 로컬 `prompt` 함수를 "세션을 정리하고 프로세스 종료"로 바꾼다(7.3).
   2. 매개변수를 읽는다: host, username, 별명, 비밀번호 파일 경로. 모두 JSON 하나로 묶어 Base64로 넣는다. Base64 문자는 스크립트 문법과 섞일 수 없다.
   3. `<host>에 접속 중...`을 일반 출력으로 찍는다.
   4. 비밀번호 파일 → `ConvertTo-SecureString` → `PSCredential`. 실패하면 종료 코드 14.
   5. `New-PSSession -ComputerName <host> -Credential <cred> -Authentication Negotiate`. 실패하면 오류를 분류해 그 종료 코드로 끝낸다(7.4).
   6. `Invoke-Command`로 원격 `prompt` 함수를 설정해 앞에 `[별명]`을 붙인다. 별명은 인자로 넘긴다. 스크립트 문자열에 이어 붙이지 않는다.
   7. `Enter-PSSession -Session $s`. 부트스트랩이 끝나면 PowerShell이 원격 프롬프트를 띄운다.
5. hq는 출력을 그대로 중계하고 입력을 그대로 넘긴다. 실제 터미널처럼, 접속 중에 미리 친 글자는 접속이 끝나면 그 서버로 간다. 접속에 실패하면 프로세스가 입력을 읽기 전에 끝나므로 내 PC에서 실행되지 않는다(7.3).

### 7.2 상태와 종료 이유

| 상태 | 뜻 | 입력 |
|---|---|---|
| 실행 중 | 프로세스가 살아 있음 | 그대로 넘김 |
| 끝남(이유) | 프로세스가 끝남 | 막힘 |

hq는 접속이 됐는지를 따로 판단하지 않는다. 화면에 원격 프롬프트가 뜨면 사람이 보고 안다. 끝난 이유는 프로세스 종료 코드로 정한다.

| 종료 코드 | 이유 | 화면 |
|---|---|---|
| 0 | USER_EXIT: 사용자가 `exit` 등으로 원격 세션을 나감 | "세션을 종료했습니다" [다시 연결] |
| 10 | AUTH_FAILED: 로그인 거부 | "로그인 거부: 비밀번호가 틀렸거나, Administrator가 아닌 로컬 계정이면 서버에 원격 관리자 설정이 필요합니다" [비밀번호 입력] [서버 설정 스크립트] |
| 11 | UNREACHABLE | "서버 응답 없음: WinRM이 꺼져 있거나 5985가 막혀 있을 수 있습니다" [다시 시도] [서버 설정 스크립트] |
| 12 | NOT_TRUSTED | "초기 설정 필요" [설정하기] |
| 13 | QUOTA | "서버의 동시 세션 한도 초과: 다른 탭을 닫거나 서버 설정 스크립트로 한도를 올리세요" [다시 시도] [서버 설정 스크립트] |
| 14 | SECRET_UNREADABLE | "저장된 비밀번호를 읽을 수 없습니다(PC나 계정이 바뀜). 다시 입력하세요" [비밀번호 입력] |
| 20 | DISCONNECTED: 원격 세션이 끊김 | "연결 끊김" [다시 연결] |
| 그 외 | UNKNOWN | 오류 원문은 터미널에 그대로 두고 "알 수 없는 오류" [다시 연결] |

hq가 탭을 닫으려고 끝낸 경우에는 이유와 상관없이 탭을 없앤다.

### 7.3 안전장치: 로컬 프롬프트는 열리지 않는다

원격 세션이 끊기면 PowerShell은 내 PC의 프롬프트로 돌아간다. 이때 입력이 남아 있으면 서버에 치려던 명령이 내 PC에서 실행될 수 있다. 끊기기 직전에 미리 쳐 둔 키도 마찬가지다.

이를 막으려고 부트스트랩이 로컬 `prompt` 함수를 바꿔 둔다. 이 함수는 로컬 프롬프트를 그리는 대신 다음을 한다.

1. 남은 원격 세션을 `Remove-PSSession`으로 정리한다.
2. 종료 코드를 정한다. 세션이 없으면 1(UNKNOWN), 세션 상태가 `Opened`면 0(사용자가 스스로 나감), 그 밖에는 20(끊김).
3. `[Environment]::Exit(<코드>)`로 바로 프로세스를 끝낸다.

PowerShell은 입력을 읽기 전에 프롬프트를 먼저 그리므로, 로컬에서 입력이 실행될 틈이 없다. hq가 프로세스가 끝난 탭의 입력을 잠그는 것은 그 위의 두 번째 방어선이다.

이 장치가 걸리기 전에 부트스트랩이 멈추면 안 된다. 그래서 안전장치를 부트스트랩 맨 앞에 두고, hq가 만든 부트스트랩이 PowerShell 5.1에서 문법 오류 없이 해석되는지를 테스트로 확인한다(13.2).

### 7.4 오류 분류

부트스트랩은 `New-PSSession` 실패를 `FullyQualifiedErrorId`, `ErrorCode`, 메시지로 분류한다. 정확한 값은 실제 오류 표본으로 테스트를 쓰고, 검증 항목 V3(14장)에서 확인한다.

- 액세스 거부 → 10 AUTH_FAILED
- 신뢰할 수 있는 호스트가 아님(TrustedHosts) → 12 NOT_TRUSTED
- 연결 불가, 시간 초과, WinRM 응답 없음 → 11 UNREACHABLE
- 동시 셸 한도 초과 → 13 QUOTA
- 나머지 → 1 UNKNOWN (원문을 터미널에 출력)

### 7.5 탭 닫기와 다시 연결

- 닫기: Ctrl+C(`\x03`)로 실행 중인 명령을 멈추고, `exit`을 입력한다(원격에서는 `Exit-PSSession`). 7.3 장치가 원격 세션을 정리하고 프로세스를 끝낸다. 2초 안에 끝나지 않으면 강제로 끝낸다.
- 강제로 끝낸 경우 서버 쪽 세션은 서버의 유휴 시간 설정이 지나야 사라진다.
- 다시 연결: 같은 탭에서 새 프로세스로 7.1부터 다시 한다. 기존 출력 뒤에 `── 다시 연결 (시각) ──` 구분선을 넣는다.
- 로그인 거부 뒤 비밀번호를 다시 넣으면 저장(덮어쓰기)하고 자동으로 다시 연결한다.
- PowerShell 3.0 이상 서버는 네트워크가 잠깐 끊기면 PowerShell이 스스로 몇 분 동안 다시 붙으려 하고 진행 표시를 보인다. 그래도 실패하면 7.3에 따라 DISCONNECTED로 끝난다.

### 7.6 여러 탭과 세션 유지

- 탭마다 별개의 powershell.exe와 WinRM 세션을 쓴다. 한 탭에서 `cd`나 변수를 바꿔도 다른 탭에는 영향이 없다.
- hq는 브라우저 연결과 상관없이 모든 세션의 출력을 계속 읽는다. 읽지 않으면 자식 프로세스가 멈추기 때문이다. 읽은 출력은 탭마다 링 버퍼(최근 1MiB)에 쌓는다. 넘쳐서 앞부분을 버릴 때는 줄바꿈 경계에서 자른다.
- 브라우저가 다시 연결되면 `GET /api/sessions`로 열린 탭을 되살리고, 각 WebSocket에 링 버퍼 내용을 먼저 보낸 뒤 실시간 출력을 이어 보낸다.
- 출력은 메모리에만 있다. 파일로 쓰지 않는다.
- 터미널 크기가 바뀌면 WebSocket으로 받아 ConPTY 크기를 바꾼다.

### 7.7 상태 점

- 화면을 열 때, [상태 새로고침]을 누를 때, 서버를 추가하거나 설정한 뒤에 모든 서버의 5985 TCP 연결을 병렬로 시도한다(서버당 1초 제한).

## 8. 보안

### 8.1 막는 상대와 받아들인 위험

| 상대 | 막는 방법 |
|---|---|
| 다른 PC | 127.0.0.1에만 연다 |
| 내 브라우저에 띄운 다른 웹페이지(CSRF, WebSocket 가로채기, DNS 리바인딩) | 입장 코드 → 쿠키, Origin·Host 검사, CSP (8.2) |
| 같은 PC의 다른 Windows 사용자, 디스크 도난 | DPAPI(CurrentUser), 사용자 프로필 폴더 |
| 엑셀 파일의 평문 비밀번호 | 메모리에서만 처리, 등록 후 삭제 경고 |
| 부트스트랩 명령 주입 | 형식 검사 + Base64 매개변수 + 인자 전달 |

받아들인 위험(막지 못한다):

- 내 계정 권한으로 도는 악성코드는 DPAPI 파일을 풀 수 있다. mstsc에 저장한 비밀번호도 조건이 같다.
- 잠그지 않은 PC는 누구나 쓸 수 있다. Windows 잠금(Win+L)에 맡긴다.
- NTLM의 한계.
  - 서버가 진짜인지 확인하지 않는다(가짜 서버, 중계 공격).
  - 엿들은 인증 내용으로 오프라인에서 비밀번호를 맞춰 볼 수 있다.
  - 두 공격 모두 공격자가 이미 내부망 중간에 있어야 한다. 서버마다 다른 긴 비밀번호로 피해를 줄인다(10장).
  - Microsoft가 NTLM을 더 개발하지 않는 기능으로 지정했으므로, 장기 대안으로 HTTPS와 SSH를 남겨 둔다(15장).

### 8.2 웹 화면 보호

- `127.0.0.1`에만 바인딩한다. 포트는 실행할 때마다 OS가 고른 빈 포트를 쓴다.
- 입장 코드
  - 실행할 때 32바이트 무작위 값을 만들고 `http://127.0.0.1:<port>/launch?code=<값>`으로 기본 브라우저를 연다.
  - `/launch`는 코드가 맞고, 처음 쓰이고, 만든 지 60초 안일 때만 세션 쿠키를 주고 `/`로 보낸다. 쿠키 값은 별도의 32바이트 무작위 값이고 `HttpOnly; SameSite=Strict; Path=/`.
  - 코드는 한 번 쓰면 버린다.
- `/launch`를 뺀 모든 요청(정적 파일 포함)은 쿠키가 맞아야 한다. 비교는 상수 시간으로 한다.
- Host 헤더는 정확히 `127.0.0.1:<port>`여야 한다.
- WebSocket은 Origin이 정확히 `http://127.0.0.1:<port>`여야 한다. 상태를 바꾸는 HTTP 요청(POST/PUT/DELETE)도 Origin이 있으면 같아야 한다.
- 응답 헤더
  - `Content-Security-Policy: default-src 'self'; connect-src 'self' ws://127.0.0.1:<port>; object-src 'none'; base-uri 'none'; frame-ancestors 'none'`
  - `X-Content-Type-Options: nosniff`
  - API 응답은 `Cache-Control: no-store`
- 외부 자원을 쓰지 않는다. xterm.js도 exe 안에 들어 있어 인터넷 없이 동작한다.

### 8.3 기록

- `logs\hq.log`에는 시작·종료, 세션 열림·끝남(서버 id, host, 종료 이유), 오류를 쓴다. 1MB짜리 3개로 돌려 쓴다.
- 비밀번호, 요청 본문, 터미널 입력·출력은 쓰지 않는다.

### 8.4 내 PC 초기 설정 (PC마다 한 번)

- TrustedHosts에는 등록한 서버의 host를 하나씩 정확히 넣는다. `*`는 쓰지 않는다.
- hq는 시작할 때, 그리고 서버를 추가·수정한 뒤 TrustedHosts를 읽는다. 빠진 host가 있으면 배너를 띄운다. 포함 여부는 정확히 일치, `*`, `*`가 들어간 이름 패턴(`*.corp.local`)을 이해해서 판단한다.
- [설정하기]를 누르면 관리자 권한 PowerShell(UAC 확인 한 번)이 고정된 스크립트를 실행한다.
  1. 내 PC의 WinRM 서비스를 켠다. 시작 유형을 자동으로 할지는 검증 V4 결과에 따라 정한다. 리스너는 만들지 않으므로 내 PC로 들어오는 포트는 열리지 않는다. `Enable-PSRemoting`이나 `winrm quickconfig`는 쓰지 않는다.
  2. 빠진 host를 TrustedHosts에 덧붙인다(`-Concatenate`). host 목록은 검증한 값만 Base64로 넘긴다.
- hq는 그 프로세스가 끝나기를 기다렸다가 다시 확인한다. UAC를 취소하면 "취소됨"으로 안내한다.
- 서버를 지워도 TrustedHosts에서는 빼지 않는다. 해가 없고 UAC 확인을 줄인다.

### 8.5 서버 초기 설정 (서버마다 한 번)

- 2012 이후 서버는 대부분 WinRM이 이미 켜져 있다. 상태 점이 ○인 서버만 손보면 된다.
- hq는 서버별 설정 스크립트를 보여 주고 [복사] 버튼을 준다.
  - `-Account`에는 그 서버의 username이 미리 들어간다.
  - "5985를 관리자 PC IP에서만 받기" 체크 상자(기본 꺼짐)를 켜면 `-AllowFrom`에 `settings.admin_ips`가 들어간다. 이 IP 목록은 같은 창에서 고치고 저장한다.
- 실행 방법: 그 서버에 마지막으로 한 번 RDP로 들어가 관리자 PowerShell에 붙여넣는다. 이미 접속되는 서버는 hq 탭에서 실행해도 된다. 스크립트가 WinRM을 다시 시작하면 그 탭은 끊기므로 다시 연결한다.
- PowerShell 2.0에서도 도는 문법만 쓴다.
- 스크립트가 하는 일(이미 된 것은 건너뛰고, 마지막에 한 일을 요약해 출력):
  1. PowerShell 2.0 미만이거나 WinRM이 없으면(2008, 2003) WMF 2.0 설치 안내를 출력하고 멈춘다.
  2. 5985 리스너가 없으면 `Enable-PSRemoting -Force`.
  3. 한도를 올린다. 계정당 동시 셸이 30보다, 셸당 메모리가 1024MB보다 낮으면 그 값으로 올린다(2008 R2 기본은 5개, 150MB).
  4. `-Account`가 서버의 로컬 계정이면서 내장 Administrator(SID가 -500으로 끝남)가 아니면 `LocalAccountTokenFilterPolicy=1`을 설정한다. 이 설정의 대가(같은 비밀번호를 쓰는 로컬 관리자 계정이 털렸을 때 다른 서버로 번지기 쉬워짐)를 함께 출력한다.
  5. `-AllowFrom`이 있으면 TCP 5985 수신 허용 규칙의 원격 주소를 그 IP들로 제한한다. 규칙은 이름이 아니라 포트로 찾는다(한국어 Windows는 규칙 이름이 다르다). 다른 시스템(모니터링 등)이 WinRM을 쓰지 않는지 확인한 뒤 켜도록 안내한다. 2003은 수동 안내만 한다.
  6. 필요하면 WinRM을 다시 시작하고, 끝으로 `Test-WSMan localhost`로 스스로 확인한다.

## 9. 실행과 배포

- `hq.exe` 파일 하나(PyInstaller onefile, 콘솔 창). 설치와 관리자 권한이 필요 없다. TrustedHosts 설정 때만 UAC 확인을 받는다.
- 실행하면
  - 이미 실행 중인지 확인한다. run.json의 포트로 내부 요청을 보내고 run.json의 비밀값으로 인증한다. 실행 중이면 새 입장 코드를 받아 브라우저만 열고 끝낸다.
  - 실행 중이 아니면(응답 없음, 인증 실패) 서버를 띄우고 run.json을 새로 쓰고 브라우저를 연다.
  - 콘솔 창에 "HQ 실행 중: 이 창을 닫으면 모든 세션이 끝납니다"를 보인다.
- 종료(창 닫기, Ctrl+C): 모든 세션을 7.5 방식으로 동시에 닫고(최대 2초) 끝낸다.
- 비정상 종료 대비: hq가 Job Object(`KILL_ON_JOB_CLOSE`)를 만들고 탭의 powershell.exe를 띄우자마자 그 Job에 넣는다. hq가 죽으면 Job이 닫히면서 자식도 끝난다. hq 자신은 Job에 넣지 않는다. 넣으면 hq가 띄운 브라우저까지 Job에 들어가 hq와 함께 닫힐 수 있다.
- 바탕화면 `09_앱_바로가기` 폴더에 바로가기를 만든다.
- 빌드: `uv run pyinstaller hq.spec` → `dist\hq.exe`.

## 10. 운영 권장 사항 (hq 밖에서 할 일)

- 서버마다 다른, 무작위 12자 이상의 비밀번호를 쓴다. hq가 서버별로 저장하므로 외울 필요가 없다.
- 비밀번호를 바꿀 때는 그 계정으로 도는 서비스와 예약 작업도 함께 바꾼다.
- 엑셀은 등록한 뒤 바로 지운다. 동료에게 건넬 때도 마찬가지다.
- 자리를 비울 때는 Win+L로 잠근다.

## 11. 범위

### 11.1 MVP에 넣는 것

1. 서버 관리: 추가·수정·삭제, 비밀번호 변경, 엑셀 일괄 등록(양식 내려받기 포함), 그룹별 목록, 검색, 정보 패널, 상태 점.
2. 터미널: 더블클릭으로 새 탭, 여러 탭, 탭 제목과 프롬프트에 별명, 새 출력 표시, Alt+1~9, 끊김 안전장치와 다시 연결, 로그인 거부 시 비밀번호 다시 입력, 새로고침해도 세션 유지, 여러 줄 붙여넣기 확인.
3. 초기 설정: 내 PC TrustedHosts 자동 추가(UAC 한 번), 서버 설정 스크립트 보기·복사.
4. 보안: 8장 전부.
5. 배포: `hq.exe` 하나, 바로가기.

### 11.2 MVP에서 빼는 것

15장의 나중 단계 후보 전부.

### 11.3 알려진 한계

- 전체 화면이나 대화형 네이티브 프로그램(diskpart 대화 모드, `nslookup` 대화 모드 등)은 WinRM에서 동작하지 않는다. 멈추면 Ctrl+C로 빠져나온다.
- 강제로 끝낸 세션은 서버의 유휴 시간이 지날 때까지 서버에 남는다.
- 2008 R2 서버는 설정 스크립트를 돌리기 전까지 계정당 동시 세션이 5개다. 두 사람이 같은 계정을 쓰므로 둘의 탭이 합산된다.

## 12. 완료 기준

아래가 모두 되면 MVP 완성이다.

| # | 기준 |
|---|---|
| AC-1 | 엑셀로 서버를 등록하면 목록에 바로 보이고, 3초 안에 모든 상태 점이 채워진다(50대 기준) |
| AC-2 | 서버를 더블클릭하면 네트워크가 정상일 때 5초 안에 `[host]: [별명] PS C:\...>` 프롬프트가 뜬다 |
| AC-3 | 2008 R2부터 2025까지 OS별로 한 대 이상에서 `hostname`, `Get-Service`, `ipconfig`가 정상 출력되고 한글이 깨지지 않는다 |
| AC-4 | 누군가 같은 서버에 Administrator로 RDP 접속해 있어도, hq로 들어갔을 때 그 RDP 세션이 끊기지 않는다 |
| AC-5 | 탭 5개(서버 3대 + 같은 서버 2개)를 오가며 오래 걸리는 명령을 돌려도 출력이 섞이거나 끊기지 않는다 |
| AC-6 | 브라우저를 새로고침하면 탭과 최근 출력이 돌아온다. hq.exe를 정상 종료하면 서버에 세션이 남지 않는다 |
| AC-7 | 연결이 끊겨도 서버에 치려던 명령이 내 PC에서 실행되지 않는다(미리 쳐 둔 입력 포함) |
| AC-8 | 비밀번호가 어떤 파일이나 로그에도 평문으로 없고, 다른 Windows 계정으로는 비밀번호 파일을 풀 수 없다 |
| AC-9 | 다른 웹페이지가 hq로 보낸 HTTP 요청과 WebSocket 연결은 모두 거절된다 |
| AC-10 | `hq.exe` 하나를 동료 PC에 복사해서 실행하면(초기 설정 한 번 뒤) AC-1~9를 똑같이 통과한다 |

## 13. 개발 방식: TDD

### 13.1 규칙

- 기능 코드보다 테스트를 먼저 쓴다. 테스트를 돌려 기대한 이유로 실패하는 것을 확인하고, 통과할 만큼만 코드를 쓴 뒤 정리한다(Red → Green → Refactor).
- 버그를 고칠 때도 그 버그를 재현하는 테스트부터 쓴다.
- 커밋은 모든 테스트가 통과하는 상태에서만 한다.

### 13.2 테스트 계층

| 계층 | 대상 | 도구 |
|---|---|---|
| 단위 | validation, inventory, excel, 부트스트랩 생성(인코딩, 주입 차단), 세션 상태와 링 버퍼(가짜 프로세스), 종료 코드 → 이유 매핑, TrustedHosts 포함 판단, 서버 설정 스크립트 생성, 웹 인증과 API(가짜 의존성) | pytest, FastAPI TestClient |
| 통합(Windows) | 부트스트랩·설정 스크립트가 PowerShell 5.1에서 문법 오류 없이 해석되는지 / DPAPI: Python으로 쓴 파일을 실제 powershell.exe가 `ConvertTo-SecureString`으로 푸는지(한글 경로 포함) / ConPTY로 실제 powershell.exe를 띄워 입출력과 크기 변경 / 7.3 안전장치: 끊긴 세션을 흉내 낸 뒤 미리 쳐 둔 명령이 실행되지 않고 종료 코드 20으로 끝나는지 / Job Object 강제 종료 / WebSocket 끝단 중계(가짜 셸) / probe(로컬 임시 TCP 서버) | pytest (`-m integration`) |
| 화면 로직 | 탭 이름 매기기, 새 출력 표시, 상태 → 화면 매핑, 검색 필터, 단축키, 여러 줄 붙여넣기 판단 | `node --test` |
| 수동 인수 | 실서버가 필요한 모든 것: 12장 완료 기준, 14장 검증 항목 | 사용자 체크리스트 |

- 개발 PC가 Windows이므로 단위와 통합 테스트는 늘 함께 돌린다: `uv run pytest`, `node --test static/`.
- 실서버와 실제 비밀번호는 자동 테스트에 쓰지 않는다. Claude는 실서버 비밀번호를 다루지 않는다. 실서버 확인은 사용자가 하고, 결과 화면이나 오류 문구를 전달한다.
- 부트스트랩의 원격 부분(`New-PSSession` 이후)은 자동 테스트로 실행할 수 없다. 생성 결과는 단위 테스트로, 실제 동작은 14장 검증 항목으로 확인한다.
- DOM을 다루는 화면 코드는 얇게 두고 수동으로 확인한다.

## 14. 검증 항목 (구현 초기에 실서버 한 대로)

사용자가 자기 PowerShell에서 돌리는 확인용 스크립트를 제공한다. 비밀번호는 `Get-Credential`로 직접 입력한다. 결과에 따라 설계의 해당 부분을 확정하거나 대체 방식으로 바꾼다.

| # | 확인할 것 | 실패하면 |
|---|---|---|
| V1 | `-NoExit -EncodedCommand`로 실행한 스크립트 끝의 `Enter-PSSession`이 원격 프롬프트로 이어진다 | 부트스트랩 방식을 바꾼다(예: 첫 입력으로 `Enter-PSSession`을 넣음) |
| V2 | 원격 프롬프트 앞에 `[별명]`이 보인다(한글 별명, PS 2.0 포함) | 별명은 탭 제목에만 보인다 |
| V3 | 오류 표본 수집: 틀린 비밀번호, TrustedHosts 없음, 5985 닫힘, 한도 초과의 `FullyQualifiedErrorId`·`ErrorCode` | 7.4 분류 표를 고친다 |
| V4 | 내 PC의 WinRM 서비스가 멈춘 상태에서도 바깥으로 접속되는지, 관리자 권한 없이 TrustedHosts를 읽을 수 있는지 | 서비스를 자동 시작으로 둔다 / 읽는 방법을 바꾼다 |
| V5 | `ipconfig`, `Get-Service`, `dir` 출력의 한글이 ConPTY를 거쳐 xterm.js까지 깨지지 않는다 | 인코딩 설정을 추가한다 |
| V6 | 도메인에 가입된 서버의 로컬 계정을 username에 어떻게 써야 하는지(`Administrator` / `.\Administrator` / `서버이름\Administrator`) | 등록 안내와 엑셀 양식 설명에 반영한다 |
| V7 | 7.3 안전장치가 실제 끊김(서버에서 WinRM 재시작)에서 동작한다 | 설계를 다시 검토한다(필수 항목) |
| V8 | PyInstaller로 만든 `hq.exe`를 백신이 막지 않는다 | 빌드 방식을 조정한다 |

## 15. 나중 단계 후보

- 여러 서버에 한 번에 명령 보내기
- 실행 기록과 감사 로그
- WinRM HTTPS(5986): 서버 진위 확인과 엿듣기 방지. 서버별 인증서가 필요하다
- SSH(2019 이상): 진짜 터미널(전체 화면 프로그램 가능), 키 인증
- Kerberos: 도메인 계정을 쓰게 되면
- 파일 주고받기 화면
- 자리 비움 자동 잠금, 트레이 아이콘
- 두 PC 사이 공유·동기화

## 16. API 개요 (참고)

| 메서드와 경로 | 용도 |
|---|---|
| `GET /launch?code=` | 입장 코드를 쿠키로 바꾸고 `/`로 보냄 |
| `GET /` | 화면 |
| `GET /api/servers` | 서버 목록(`has_password` 포함, 비밀번호 없음) |
| `POST /api/servers` | 서버 추가(정보 + 비밀번호) |
| `PUT /api/servers/{id}` | 정보 수정 |
| `PUT /api/servers/{id}/password` | 비밀번호 덮어쓰기 |
| `DELETE /api/servers/{id}` | 삭제(비밀번호 파일, 열린 탭 포함) |
| `POST /api/probe` | 상태 점 확인 |
| `GET /api/excel/template` | 엑셀 양식 |
| `POST /api/excel/preview` | 엑셀 미리보기(파일 업로드) |
| `POST /api/excel/apply` | 미리보기 결과 등록(`preview_id`, `overwrite`) |
| `GET /api/setup/trustedhosts` | 빠진 host 목록 |
| `POST /api/setup/trustedhosts` | 관리자 권한으로 추가(UAC) |
| `GET /api/servers/{id}/setup-script` | 서버 설정 스크립트 |
| `PUT /api/settings` | `admin_ips` 저장 |
| `GET /api/sessions` | 열린 세션 목록 |
| `POST /api/sessions` | 세션 열기 |
| `POST /api/sessions/{id}/reconnect` | 다시 연결 |
| `DELETE /api/sessions/{id}` | 세션 닫기 |
| `WS /ws/sessions/{id}` | 터미널 중계. 서버 → 브라우저: 링 버퍼 다음 실시간 출력, 상태 변경. 브라우저 → 서버: 입력, 크기 변경 |
| `POST /internal/launch-code` | 두 번째 실행이 새 입장 코드를 받음(run.json 비밀값으로 인증) |
